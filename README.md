# Kronoterm KSM (Modbus) для Home Assistant

Інтеграція Home Assistant для теплових насосів **Kronoterm** з контролером **KSM / TT4000**.
Працює локально, напряму через Modbus, без хмари Kronoterm.

Назви сутностей, стани (режими, функції, розклад) і тексти аварій **автоматично
перекладаються** мовою Home Assistant: **українська, англійська, словенська**
(інші мови — англійською).

```
KSM ──RS485 (TEX)──▶ Pico W з прошивкою-мостом ──Wi-Fi, TCP 502──▶ Home Assistant: kronoterm_ksm
```

Замість Pico W можна взяти готовий шлюз RS485 → Modbus TCP.

## Що вміє

- **178 сутностей:** температури, тиск, потужність, COP/SCOP, лічильники енергії, мотогодини,
  стани насосів і компресора, режими, уставки, зміщення ECO/COMFORT, криві опалення, антилегіонела, відпустка.
- **Термостати:** гаряча вода, бак, контури 1–4, басейн.
  Контур з кімнатним термостатом KT-1/KT-2 керує кімнатною температурою (17–27 °C);
  контур без нього і бак — розрахунковою подачею (регулятор зсуває криву).
- **Енергія за призначенням:** опалення / гаряча вода / інше / разом, оцінка енергії циркуляційних
  насосів. Лічильники зберігаються після перезапуску HA.
- **Аварії й попередження** текстом мовою HA (187 текстів з документації Kronoterm), кнопка скидання помилки.
- Налаштування через інтерфейс HA. Регістри, яких немає на вашій моделі, пропускаються автоматично.
- Без зовнішніх бібліотек: власний Modbus-клієнт (RTU через TCP або Modbus TCP).

## Обладнання

- Raspberry Pi Pico W (або Pico 2 W) + модуль RS485 (MAX485)
- Pico GPIO0 → DI, GPIO1 ← RO, GPIO2 → DE+RE модуля
- Модуль → клемник **TEX** на платі KSM: A+, B-, GND
- Шина: 115200 бод, 8N1 (старі WPG на контролері V2.x: 19200), Modbus-адреса насоса 20

## Встановлення

### 1. Прошивка моста (Pico W)
1. В ESPHome Builder скопіюйте папку `esphome/components/kt_bridge` у `/config/esphome/components/kt_bridge`.
2. Створіть пристрій з `esphome/kronoterm-bridge.yaml`, у `secrets.yaml` впишіть Wi-Fi
   (зразок: `esphome/secrets.example.yaml`), залийте на Pico.
3. Бажано дати Pico статичну IP-адресу (розділ `manual_ip` у файлі).

Прошивка лише пересилає Modbus між Wi-Fi (TCP, порт 502) і RS485, сутностей сама не створює.
На шині RS485 має бути лише один Modbus-майстер: якщо на цьому Pico була інша прошивка
Kronoterm, її замінює ця.

### 2. Інтеграція
- **HACS:** HACS → ⋮ → Custom repositories → адреса цього репозиторію, тип *Integration* →
  встановити **Kronoterm KSM (Modbus)** → перезапустити HA.
- **Вручну:** скопіюйте `custom_components/kronoterm_ksm` у `/config/custom_components/` → перезапустити HA.

### 3. Додати насос
Налаштування → Пристрої та служби → Додати інтеграцію → **Kronoterm KSM (Modbus)**:
- адреса — IP Pico (або шлюзу), порт **502**;
- протокол — **RTU через TCP** для Pico W, **Modbus TCP** для готових шлюзів;
- Modbus-адреса — **20**.

У параметрах інтеграції можна змінити інтервал опитування (типово 10 с) і множник теплової енергії.

## Перехід зі старої прошивки ESPHome (kronoterm.yaml)

ID сутностей інтеграції закріплені й не залежать від мови: `sensor.kronoterm_<ключ>`,
`climate.kronoterm_loop_1` тощо. Старі ID інші, тому:

1. **Видаліть старий шаблонний пакет** `config/packages/kronoterm_climate.yaml` (якщо був) і
   перезавантажте YAML. Інакше нові термостати отримають ID з `_2`.
2. **Видаліть старий пристрій ESPHome «kronoterm»**: Налаштування → Пристрої та служби → ESPHome →
   kronoterm → ⋮ → Видалити. Інакше старі ID зайняті, і нові сутності отримають `_2`.
3. Залийте на Pico прошивку моста і додайте інтеграцію (див. вище).
4. **Панелі:** вставте `dashboards/kronoterm_panel.yaml` (стиль Kronoterm, потрібен `button-card`)
   або `dashboards/kronoterm_simple.yaml` — вони вже під нові ID.
5. **Автоматизації й скрипти:** замініть ID за таблицею [`dashboards/ENTITY_MAP.md`](dashboards/ENTITY_MAP.md).
   Увага: стани вибору й текстових сутностей тепер ключі (`off` / `normal` / `schedule`,
   `heating` / `dhw` / `standby`…), а не український текст.
6. **Панель «Енергія»:** додайте нові «Енергія: …» сенсори. Історія старих лічильників
   залишиться в статистиці під старими ID.

## Нотатки

- **Бак:** його уставку насос рахує сам за кривою (регістр 2032 лише читається), тому регулятор
  термостата бака зсуває криву бака.
- **Адаптивна крива** контуру працює лише з кімнатним термостатом KT; тоді точки кривої веде насос,
  а термостат у HA керує кімнатною температурою.
- **Енергія:** для панелі «Енергія» краще брати «Енергія: разом (розрахунок)», а не лічильник
  насоса: той рахує тільки цілими кВт·год.
- Адреси регістрів у коді = номер у документації Kronoterm (CNS) мінус 1.

## Розробка

- `tools/spec.py` — одне джерело всіх сутностей і їхніх назв трьома мовами.
- `tools/alarm_source.json` + `tools/alarm_texts.py` — біти аварій і тексти (sl / en / uk).
- `cd tools && python3 generate.py` — генерує `registers.py`, `alarms.py`, `strings.json` і переклади.
- `python3 -m pytest tests` — тести на імітаторі насоса (Modbus RTU через TCP і Modbus TCP,
  декодування, переклади, усі сутності на заглушках HA).

## Стан

Версія 0.1.0. Протестовано на імітаторі насоса; на справжньому насосі й Home Assistant —
у процесі перевірки. Компонент моста `kt_bridge` ще не перевірено компіляцією в ESPHome.
